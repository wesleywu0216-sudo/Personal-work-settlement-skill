# 输入、映射与异常规则

## 后台明细必需字段

`对账单ID`、`游戏名称`、`企业名称`、`月份`、`结算周期`、`流水总计`、`非结算金额`、`退款金额`、`对账金额`、`渠道费率`、`渠道费`、`税率`、`税费`、`结算基数`、`比例`、`收入金额`、`合同开始时间`、`合同终止时间`、`合同初审状态`、`合同复审状态`。

百分比可为 Excel 百分比值或带 `%` 的文本；金额必须能解析为十进制数。`对账单ID` 为空且游戏名称为“总计”的页尾合计行不作为业务明细。

## 基础筛选

- 合同初审和复审状态均须包含“通过”且不得包含“不通过”；例如“电子签审核通过”可进入，“审核不通过”不可进入。
- 收入金额必须大于等于1元；小于1元按基础筛选排除。
- 两项条件都满足后，才进行人工排除和乙方资料匹配。

## 乙方公司信息表

必需字段：`公司`、`开户银行`、`银行帐号`、`联系人`、`电话`。银行帐号和电话按文本读取；超出 JavaScript 安全整数范围的数字账号必须要求用户把源单元格改为文本。

匹配前只清理首尾空白、不可见空白和全角空格。完全一致的重复资料可去重；同公司存在不一致资料时阻断该公司的产品。

## 人工排除 JSON

```json
[
  {
    "month": "202607",
    "game": "特殊产品",
    "company": "示例公司",
    "reason": "本批次经确认不结算"
  }
]
```

月份 `YYYY-MM` 与 `YYYYMM` 视为同月。游戏名在比较前移除末尾 PC 版标识。排除原因不能为空。

## 控制模板单元格

| 单元格 | 写入内容 |
|---|---|
| A3 | `TO 企业名称` |
| A5 | `yyyy.mm.dd-yyyy.mm.dd` 结算周期 |
| C5 | 标准化游戏名称 |
| D5 | 固定“付费下载” |
| E5:G5 | 流水总计、非结算金额、退款金额 |
| H5 | `=ROUND(E5-F5-G5,2)` |
| I6 | 渠道费率 |
| J6 | `=ROUND(H5*I6,2)` |
| K6 | 分成比例 |
| L6 | 对 `(H5-J6)*K6` 执行十进制半入舍入；公式加入仅用于抵消二进制误差的正负 `0.000000001` |
| M5 | `=L6` |
| M7 | `=SUM(M5:M6)` |
| B15:B19 | 公司、银行、账号、联系人、电话（含原标签） |

模板的合并单元格、字体、边框、行高、列宽、甲方信息和打印布局必须保留。A5、E5及所有旧外部工作簿公式必须替换，输出公式不得包含 `[`、`]`、`_xlfn` 或外部工作簿名。

金额单元格 `E5:H5`、`J6`、`L6:M7` 使用数字格式 `#,##0.00`；百分比单元格继续使用 `0.00%`。

## 逐条金额检查

1. 对账金额 = 流水总计 - 非结算金额 - 退款金额；
2. 渠道费 = 对账金额 × 渠道费率，按分四舍五入；
3. 税费 = 0；
4. 结算基数 = 对账金额 - 渠道费；
5. 收入金额 = 结算基数 × 比例，按分四舍五入；
6. 生成文件最终金额与后台收入金额差异必须小于 0.005 元。

## 阻断与继续

- 缺少后台或公司表必需列：整批停止；
- 月份不唯一、模板工作表/关键单元格缺失、汇总文件已存在：整批停止；
- 重复产品、税费非零、金额差异、乙方资料问题、同名产品文件：仅阻断受影响产品，其余继续；
- 所有排除和异常都必须进入批次汇总，不能静默跳过。
