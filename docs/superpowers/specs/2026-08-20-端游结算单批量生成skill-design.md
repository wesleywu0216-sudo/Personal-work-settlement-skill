# 端游结算单批量生成 Skill 设计规格

## 1. 背景与目标

当前端游结算工作需要从后台导出的《财务对账明细》逐个产品制作结算确认函。目标是将该流程沉淀为一个可重复使用的 Codex Skill：用户每月提供一份后台明细、一份乙方公司信息表和一份已确认的端游结算单模板，Skill 自动筛选符合条件的产品、补全乙方资料、生成独立结算单、复核金额，并输出生成及排除清单。

首版只处理端游普通结算单，不改变后台数据，不向外部发送文件，也不判断后台原始数据和合同内容是否真实正确。

## 2. 输入

### 2.1 必需文件

1. 后台财务对账明细 `.xlsx`，至少包含以下字段：
   - 对账单ID
   - 游戏名称
   - 企业名称
   - 月份、结算周期
   - 流水总计、非结算金额、退款金额、对账金额
   - 渠道费率、渠道费
   - 税率、税费、结算基数
   - 比例、收入金额
   - 合同开始时间、合同终止时间
   - 合同初审状态、合同复审状态
2. 一份端游结算确认函模板 `.xlsx`，版式以《崩坏：星穹铁道 （端游）202606.xlsx》为控制模板。
3. 一份乙方公司信息表 `.xlsx`，至少包含以下字段：
   - 公司
   - 开户银行
   - 银行帐号
   - 联系人
   - 电话

公司信息表以《联运端游公司信息列表.xlsx》为当前控制样例。银行账号和电话必须按文本读取和写入，避免前导零丢失或长数字精度变化。

### 2.2 可选参数

- 输出目录；默认按月份输出到 `D:\Codex\结算自动化\端游结算单\YYYYMM\`。
- 是否覆盖同名文件；首版默认不覆盖，发现同名文件时写入异常清单。
- 本批次人工排除项，可按 `月份 + 游戏名称 + 企业名称` 指定，并必须填写排除原因。当前样例明确排除“白银之城（PC版）—上海乐元素世界科技有限公司”，原因为“收入 0.1 元，经确认不结算”。

## 3. 筛选规则

一条后台明细只有同时满足以下条件才进入生成范围：

1. `合同初审状态 = 审核通过`；
2. `合同复审状态 = 审核通过`，不把“电子签审核通过”“待签约”“电子合同生成中”等状态视为等价；
3. `收入金额 != 0`。

未满足条件的记录不生成结算单，并在汇总清单中记录排除原因。

通过上述基础条件后，再应用本批次人工排除项。人工排除只作用于明确指定的产品，不将“收入 0.1 元”推导为全局金额门槛，也不影响其他同金额产品。

合同开始和终止日期只做风险提示，不作为首版额外筛选条件，避免改变用户已经确认的筛选口径。如果结算周期不在合同有效期内，汇总清单必须标记“合同日期风险”。

## 4. 分组与去重

- 默认按 `月份 + 游戏名称 + 企业名称` 生成一份结算单。
- 游戏名称在比较前去除结尾的中文或英文括号版本标识，如“（PC版）”或“(PC版)”。
- 同一月份、同一标准化游戏名称、同一企业出现多条符合条件的记录时，不自动合并或任选一条；该组停止生成并写入“重复产品记录”异常，等待人工确认。
- 当前样例按基础条件筛选得到 18 条记录、18 个产品；应用“白银之城”人工排除项后，最终进入生成范围的为 17 条记录、17 个产品、无重复产品。

## 5. 字段映射

| 结算单位置/字段 | 数据来源或规则 |
|---|---|
| 甲方名称及甲方固定信息 | 保留模板原内容 |
| `TO 公司名称` | 后台明细“企业名称” |
| 乙方信息—公司名称 | 公司信息表“公司”，与后台明细“企业名称”精确匹配 |
| 乙方开户银行 | 公司信息表“开户银行” |
| 乙方银行账号 | 公司信息表“银行帐号”，按文本写入 |
| 乙方联系人 | 公司信息表“联系人” |
| 乙方电话 | 公司信息表“电话”，按文本写入 |
| 结算周期 | 后台明细“结算周期”，显示为 `yyyy.mm.dd-yyyy.mm.dd` |
| 游戏名称 | 后台明细“游戏名称”，去掉“（PC版）”或“(PC版)” |
| 类型 | 固定为“付费下载” |
| 订单金额 | 后台明细“流水总计” |
| 不结算金额 | 后台明细“非结算金额” |
| 退款金额 | 后台明细“退款金额” |
| 结算金额 | `ROUND(订单金额-不结算金额-退款金额, 2)` |
| 渠道费率 | 后台明细“渠道费率” |
| 渠道费金额 | `ROUND(结算金额×渠道费率, 2)` |
| 分成比例 | 后台明细“比例” |
| 最终结算金额 | `ROUND((结算金额-渠道费金额)×分成比例, 2)` |
| 总计 | 最终结算金额 |

### 5.1 乙方公司匹配与缺失处理

- 匹配键为后台明细“企业名称”与公司信息表“公司”。比较前只清理首尾空格、不可见空白和全角空格，不做简称、别名或模糊匹配。
- 精确匹配到唯一记录且公司、开户银行、银行帐号、联系人、电话均非空时，该产品才可生成。
- 找不到公司、关键字段为空，或同一公司存在多条不一致记录时，不生成该公司对应的全部产品；在异常清单中列出公司、受影响产品和待补字段，并明确提示用户补充公司信息表后重跑。
- 同一公司存在内容完全一致的重复记录时可按一条处理，但必须在运行信息中记录去重数量。
- 不允许从其他产品、历史结算单或名称相近的公司自动借用乙方资料。

## 6. 税费处理

当前模板没有税费展示字段。首版生成前执行以下控制：

- 若符合筛选条件的记录 `税费 = 0`，按标准模板生成；
- 若符合筛选条件的记录 `税费 != 0`，停止生成该产品并写入“模板缺少税费字段”异常；
- 不将税费并入“不结算金额”，不通过隐藏调整让结算单表面勾稽，因为这会改变字段含义。

## 7. 金额核对与生成门槛

每个产品在导出前必须通过以下检查：

1. 后台明细内部关系：
   - 对账金额 = 流水总计 - 非结算金额 - 退款金额；
   - 渠道费 = 对账金额 × 渠道费率，按分四舍五入；
   - 税费为 0；
   - 结算基数 = 对账金额 - 渠道费；
   - 收入金额 = 结算基数 × 比例，按分四舍五入。
2. 生成后的结算单最终金额必须与后台明细“收入金额”相等，允许差异小于 0.005 元。
3. 任一检查失败时不输出该产品的正式结算单，只在异常清单中记录实际值、复算值和差额。

计算过程采用“先转为分、整数计算、再还原为元”的等价逻辑，避免二进制小数造成 0.01 元假差异。

## 8. 模板处理

- 以模板为母版，保留原有合并单元格、字体、边框、行高、列宽、备注、甲方信息和打印布局。
- 移除或替换模板中对外部工作簿（如 `[1]端游`）的引用，使每份输出文件独立打开。
- 输入字段写入固定单元格；计算字段使用本工作簿内部公式。
- 不改写用户提供的源文件和模板原件。

## 9. 输出

### 9.1 产品结算单

每个合格产品输出一份 `.xlsx`：

`游戏名称 （端游）YYYYMM.xlsx`

示例：

`崩坏：星穹铁道 （端游）202607.xlsx`

### 9.2 批次汇总清单

每次运行同时输出一份：

`端游结算单生成汇总_YYYYMM.xlsx`

至少包含以下工作表：

1. `生成清单`：产品、企业、月份、收入金额、输出文件名、核对状态；
2. `排除清单`：原始行号、产品、企业、收入、合同状态、排除类型（基础筛选/人工排除）和排除原因；
3. `异常清单`：重复产品、字段缺失、税费非零、金额差异、同名文件等；
4. `运行信息`：源文件、公司信息表、模板、运行时间、筛选规则、人工排除项和输出目录。

## 10. Skill 交互流程

1. 用户提供后台明细、乙方公司信息表和模板文件路径；
2. Skill 展示源文件月份、明细数量、基础条件通过数量、人工排除数量、最终生成数量、乙方资料匹配数量、待补公司数量和异常数量；
3. 若月份不唯一、模板结构不匹配、乙方资料缺失或存在无法自动决定的问题，列出问题；缺失乙方资料的产品停止生成，其余产品可继续由用户整批确认；
4. 用户确认后批量生成；
5. Skill 完成金额、公式、文件数量和版式验证；
6. 返回输出目录、成功数量、排除数量和异常数量。

首版不要求用户逐个确认产品，只对整批生成进行一次确认。

## 11. 错误处理与安全边界

- 源文件缺少必需字段：整批停止；
- 公司信息表缺少必需列：整批停止；
- 模板缺少关键单元格或结构发生变化：整批停止；
- 单条数据存在重复、税费、计算差异、乙方资料缺失或同名文件：只停止该产品；同一乙方资料缺失时停止该公司对应的全部产品，其余产品继续；
- 不覆盖同名文件，不删除用户文件；
- 不修改源明细和模板；
- 所有数据、缓存和输出默认保存在 `D:\Codex` 下；
- 不发送邮件、企业微信或上传外部系统。

## 12. 验证与验收标准

使用当前三份样例文件进行首轮验收：

1. 基础筛选结果必须为 18 条记录、18 个产品；人工排除“白银之城”后，最终生成范围必须为 17 条记录、17 个产品；
2. 当前公司信息表可精确匹配最终生成范围内的全部 17 个产品、15 家乙方公司；无需补充“上海乐元素世界科技有限公司”，因为其唯一对应产品“白银之城”已人工排除；输出必须为 17 份产品结算单和 1 份批次汇总清单；
3. 每份产品结算单游戏名称不含“（PC版）”；
4. 每份产品结算单类型为“付费下载”；
5. TO公司与后台明细企业名称一致，乙方公司、开户银行、银行账号、联系人、电话与公司信息表逐字段一致；银行账号和电话无科学计数法、前导零丢失或精度变化；
6. 每份最终结算金额与后台明细“收入金额”一致；
7. 输出文件中不存在外部工作簿引用和公式错误；
8. 汇总清单完整记录基础筛选排除的 10 条记录及原因，并另行记录 1 条人工排除：“白银之城（PC版）—上海乐元素世界科技有限公司—收入 0.1 元，经确认不结算”；不得将其记录为乙方公司信息缺失；
9. 逐页渲染检查结算单无内容截断、错位或版式破坏；
10. 原始模板、后台明细和公司信息表的文件哈希保持不变。

## 13. 非目标与后续扩展

首版不包含：

- 从公司信息表以外的来源自动查询或推断乙方资料；
- 自动处理税费非零的结算单模板；
- 自动合并同一产品的多合同记录；
- 对接后台接口、邮箱或企业微信；
- 校验合同和后台源数据是否真实正确。

后续可扩展公司别名映射、税费版模板、合同有效期强拦截、自动归档及跨月重跑能力。
